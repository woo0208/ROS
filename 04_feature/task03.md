# ROS 및 컴퓨팅 기초 조사

## 1. ROS1과 ROS2의 통신 방식 관점에서 차이를 설명하라

ROS(Robot Operating System)는 로봇 소프트웨어의 여러 프로그램(Node)이 서로 데이터를 주고받을 수 있도록 통신 기능을 제공한다. ROS1과 ROS2는 모두 Topic, Service 등의 개념을 사용하지만, 실제 통신 구조에는 큰 차이가 있다.

### ROS1의 통신 방식

ROS1은 기본적으로 **ROS Master를 중심으로 노드를 검색하고 연결하는 구조**를 사용한다.

동작 과정은 다음과 같다.

1. ROS Master(`roscore`)가 실행된다.
2. 각 Node는 자신의 이름과 Topic, Service 등의 정보를 ROS Master에 등록한다.
3. Subscriber는 ROS Master에게 원하는 Topic의 Publisher 위치를 요청한다.
4. Publisher와 Subscriber의 위치를 확인한 이후에는 두 Node가 직접 연결된다.
5. 실제 Topic 데이터는 일반적으로 **TCPROS**를 이용하여 전달된다.

즉, ROS Master가 모든 데이터를 중계하는 것은 아니며, **Node를 검색하고 서로 연결하기 위한 중앙 관리 역할**을 한다.

구조를 간단히 표현하면 다음과 같다.

    Node A ──등록──▶ ROS Master ◀──조회── Node B
      │                              │
      └──────── TCPROS 직접 통신 ────┘

ROS Master가 존재하지 않으면 새로운 Node나 Topic을 검색하기 어려워지기 때문에 중앙 관리 구조에 대한 의존성이 존재한다.

---

### ROS2의 통신 방식

ROS2는 ROS1의 ROS Master와 같은 중앙 관리 서버를 기본적으로 사용하지 않는다.

대신 **DDS(Data Distribution Service)**를 통신 기반으로 사용하며, DDS의 Discovery 기능을 통해 Node들이 네트워크에서 서로를 자동으로 검색한다.

구조는 다음과 같이 표현할 수 있다.

    Node A ◀──────── DDS ────────▶ Node B
      ▲                            ▲
      │                            │
      └────────▶ Node C ◀─────────┘

각 Node가 DDS를 통해 다른 Node를 발견할 수 있으므로 ROS1의 `roscore`와 같은 중앙 Master가 필요하지 않다.

또한 ROS2에서는 **QoS(Quality of Service)**를 이용하여 통신 특성을 세부적으로 설정할 수 있다.

대표적인 QoS 설정에는 다음과 같은 것이 있다.

- Reliability: 데이터 전달 신뢰성
- Durability: 과거 데이터 보존 여부
- History: 메시지 저장 방식
- Depth: 저장할 메시지 개수
- Deadline: 데이터 전달 주기 제한
- Lifespan: 메시지의 유효 시간

따라서 ROS2는 다양한 네트워크 환경과 실시간 시스템, 다수의 로봇 또는 분산 시스템에 보다 유연하게 적용할 수 있다.

### ROS1과 ROS2 통신 구조 비교

| 항목 | ROS1 | ROS2 |
|---|---|---|
| 기본 통신 구조 | ROS Master 기반 검색 | DDS 기반 분산 검색 |
| 중앙 서버 | ROS Master 필요 | 기본적으로 불필요 |
| 대표 통신 방식 | TCPROS | DDS/RTPS |
| Node 검색 | ROS Master를 이용 | DDS Discovery 이용 |
| QoS 설정 | 제한적 | 다양한 QoS 지원 |
| 실시간 시스템 지원 | 제한적 | ROS1보다 강화 |
| 분산 시스템 확장성 | 상대적으로 제한적 | 상대적으로 우수 |
| 네트워크 환경 설정 | 비교적 단순 | DDS 설정에 따라 복잡할 수 있음 |

핵심적으로 **ROS1은 중앙의 ROS Master를 이용하여 Node를 검색한 뒤 Node끼리 직접 통신하는 방식이고, ROS2는 DDS를 사용하여 중앙 Master 없이 분산된 Node들이 서로를 발견하고 통신할 수 있는 방식**이라는 차이가 있다.

## 2. ROS1의 통신 미들웨어인 TCPROS와 ROS2의 통신 미들웨어인 DDS의 차이를 설명하라

엄밀하게 말하면 TCPROS와 DDS는 완전히 동일한 계층의 기술은 아니다.

- **TCPROS**: ROS1에서 Topic 메시지를 TCP를 통해 전달하기 위한 ROS 전용 전송 프로토콜
- **DDS**: 분산 실시간 시스템을 위한 데이터 중심 통신 미들웨어 표준

따라서 DDS는 단순한 데이터 전송 프로토콜보다 더 많은 기능을 제공한다.

### TCPROS

TCPROS는 ROS1에서 가장 일반적으로 사용되는 Topic 전송 방식이다.

TCP(Transmission Control Protocol)를 기반으로 하기 때문에 다음과 같은 특성을 가진다.

- 연결 지향 통신
- 데이터 전달 신뢰성 보장
- 패킷 순서 보장
- 손실된 패킷 재전송
- Publisher와 Subscriber 사이의 직접 연결

예를 들어 카메라 Node가 이미지 데이터를 발행하고 다른 Node가 이를 구독한다면 ROS Master를 통해 서로의 위치를 확인한 뒤 TCPROS 연결을 생성하여 데이터를 전달할 수 있다.

하지만 TCPROS 자체에는 DDS처럼 복잡한 QoS 정책이나 자동 분산 Discovery 기능이 존재하지 않는다.

---

### DDS

DDS(Data Distribution Service)는 OMG(Object Management Group)에서 표준화한 **데이터 중심 Publish/Subscribe 방식의 분산 통신 미들웨어**이다.

ROS2에서는 DDS 계열 미들웨어를 이용하여 Node 간 통신을 수행한다.

DDS는 일반적으로 다음과 같은 기능을 제공한다.

- 자동 Participant Discovery
- Publish/Subscribe 통신
- 다양한 QoS 설정
- 데이터 신뢰성 제어
- 데이터 보존 정책
- 실시간 통신 지원
- 다수 장치 간 분산 통신
- UDP 기반 RTPS 통신 등

DDS에서는 데이터를 단순히 송수신하는 것뿐만 아니라 **데이터를 어떤 품질과 정책으로 전달할 것인지**를 설정할 수 있다.

예를 들어 센서 데이터의 경우 최신 데이터가 중요하기 때문에 일부 패킷이 유실되어도 빠른 전달을 우선할 수 있다.

반대로 제어 명령처럼 데이터 유실이 문제가 되는 경우 신뢰성 있는 전송을 선택할 수 있다.

### TCPROS와 DDS 비교

| 항목 | TCPROS | DDS |
|---|---|---|
| 사용 | ROS1 | ROS2 |
| 성격 | ROS 전용 TCP 전송 프로토콜 | 분산 통신 미들웨어 표준 |
| 기본 통신 | TCP 기반 | DDS 구현에 따라 RTPS/UDP 등의 방식 사용 |
| 중앙 Master | ROS Master와 함께 사용 | 필요하지 않음 |
| 자동 Discovery | 자체적으로 제공하지 않음 | 지원 |
| QoS | 매우 제한적 | 다양한 QoS 제공 |
| 신뢰성 설정 | TCP 특성상 신뢰성 전송 | Reliable/Best Effort 선택 가능 |
| 실시간 통신 | 제한적 | 실시간·분산 시스템을 고려하여 설계 |
| 확장성 | 비교적 낮음 | 대규모 분산 시스템에 적합 |

따라서 ROS1의 TCPROS는 비교적 단순한 TCP 기반 통신 방법인 반면, ROS2에서 사용하는 DDS는 **Discovery, QoS, 분산 통신 및 실시간 통신 기능까지 포함하는 보다 포괄적인 미들웨어**라는 차이가 있다.

## 3. 실시간 시스템(Real-Time System)의 정의를 조사하라

**실시간 시스템(Real-Time System)**이란 특정 작업의 결과가 정확한 것뿐만 아니라, **정해진 시간 제한(Deadline) 안에 결과가 생성되는 것까지 시스템의 정확성에 포함되는 시스템**을 의미한다.

즉,

> 올바른 결과를 계산하는 것뿐만 아니라 필요한 시간 안에 결과를 제공하는 것이 중요하다.

일반적인 컴퓨터 시스템에서는 처리 시간이 조금 늦어지더라도 결과가 정확하면 문제가 되지 않을 수 있다.

그러나 실시간 시스템에서는 Deadline을 초과하면 계산 결과 자체가 정확하더라도 시스템 요구사항을 만족하지 못한 것으로 판단할 수 있다.

예를 들어 자동차의 충돌 방지 시스템이 장애물을 정확하게 인식하더라도 충돌 이후에 브레이크 명령을 발생시키면 의미가 없다.

### 실시간 시스템의 종류

#### 1. Hard Real-Time System

Deadline을 반드시 만족해야 하는 시스템이다.

Deadline을 한 번이라도 초과하면 심각한 시스템 오류로 판단될 수 있다.

예:

- 자동차 에어백 제어
- 항공기 제어 시스템
- 산업용 안전 제어 시스템
- 의료기기 제어 시스템

#### 2. Soft Real-Time System

Deadline을 초과해도 시스템 전체가 실패하지는 않지만 성능이나 서비스 품질이 감소하는 시스템이다.

예:

- 영상 스트리밍
- 음성 통신
- 온라인 게임
- 멀티미디어 처리

#### 3. Firm Real-Time System

Deadline을 초과한 결과는 더 이상 가치가 없지만, 일부 Deadline 실패가 전체 시스템의 치명적인 고장으로 이어지지는 않는 시스템이다.

예를 들어 특정 시간 내에 처리되지 않은 센서 데이터가 이후에는 의미가 없어 폐기되는 시스템이 이에 해당할 수 있다.

### 핵심

실시간 시스템에서 중요한 것은 단순히 **처리 속도가 빠른 것**이 아니다.

가장 중요한 특성은

**"정해진 시간 내에 작업 완료를 보장하거나 예측할 수 있는가"**

이다.

따라서 평균적으로 매우 빠른 시스템이라도 실행 시간이 불규칙하여 Deadline을 보장할 수 없다면 엄격한 의미의 실시간 시스템이라고 보기 어렵다.

## 4. GPL 라이선스와 Apache 2.0 라이선스의 차이를 설명하라

GPL과 Apache License 2.0은 모두 대표적인 오픈소스 소프트웨어 라이선스이지만, 소프트웨어를 수정하거나 배포할 때 요구되는 조건에서 큰 차이가 있다.

### GPL(GNU General Public License)

GPL은 대표적인 **Copyleft(카피레프트) 라이선스**이다.

GPL 프로그램을 수정하거나 GPL 코드와 결합한 파생 저작물을 GPL 조건에 따라 배포하는 경우 일반적으로 해당 소스 코드 역시 GPL 조건으로 제공해야 한다.

주요 특징은 다음과 같다.

- 소프트웨어 사용 가능
- 소스 코드 수정 가능
- 재배포 가능
- 배포 시 GPL의 조건을 유지해야 함
- 파생 저작물을 배포할 경우 소스 코드 공개 의무가 발생할 수 있음
- 독점적인 Closed Source 제품에 통합할 때 제약이 상대적으로 큼

GPL의 목적은 소프트웨어가 수정되고 재배포되더라도 사용자에게 소프트웨어를 사용·수정·배포할 자유가 계속 보장되도록 하는 것이다.

---

### Apache License 2.0

Apache License 2.0은 **Permissive License(허용적 라이선스)**이다.

Apache 2.0 코드를 수정하여 상용 제품에 포함하는 것이 가능하며, 자신의 전체 프로그램을 반드시 오픈소스로 공개해야 하는 것은 아니다.

주요 특징은 다음과 같다.

- 상업적 사용 가능
- 수정 가능
- 재배포 가능
- 비공개 소프트웨어에 포함 가능
- 전체 파생 프로그램의 소스 공개를 강제하지 않음
- 저작권 및 라이선스 고지 유지 필요
- 변경한 파일에 변경 사실을 표시해야 하는 조건이 있음
- 명시적인 특허(Patent) 라이선스 조항을 포함함
- NOTICE 파일이 존재하는 경우 관련 고지 조건을 따라야 함

### GPL과 Apache 2.0 비교

| 항목 | GPL | Apache License 2.0 |
|---|---|---|
| 종류 | Copyleft | Permissive |
| 상업적 이용 | 가능 | 가능 |
| 수정 | 가능 | 가능 |
| 재배포 | 가능 | 가능 |
| 파생 프로그램 소스 공개 | 배포 방식 및 결합 관계에 따라 요구됨 | 전체 프로그램 공개 의무 없음 |
| 독점 소프트웨어 사용 | 상대적으로 제약이 큼 | 비교적 자유로움 |
| 라이선스 고지 | 필요 | 필요 |
| 특허 조항 | 버전에 따라 차이 | 명시적인 특허 라이선스 조항 존재 |

따라서 가장 큰 차이는 **GPL은 파생 프로그램에도 자유 소프트웨어의 조건을 유지하도록 하는 Copyleft 성격이 강한 반면, Apache 2.0은 수정된 코드를 상용·비공개 프로그램에 활용할 수 있는 자유도가 더 높은 Permissive 라이선스**라는 것이다.

※ GPL은 버전(GPLv2, GPLv3)에 따라 세부 조건이 다르므로 실제 소프트웨어 개발에서는 해당 GPL 버전을 확인해야 한다.

## 5. 멀티 프로세싱(Multiprocessing)을 설명하라

**멀티 프로세싱(Multiprocessing)**이란 하나의 컴퓨터에서 여러 개의 프로세스(Process)를 동시에 또는 병렬적으로 실행하는 방법을 의미한다.

프로세스는 실행 중인 하나의 프로그램 단위이며, 일반적으로 각각 독립적인 메모리 공간을 가진다.

예를 들어 다음과 같이 여러 작업을 별도의 프로세스로 실행할 수 있다.

    CPU Core 1 ── Process A
    CPU Core 2 ── Process B
    CPU Core 3 ── Process C
    CPU Core 4 ── Process D

멀티코어 CPU에서는 여러 프로세스를 실제로 동시에 실행하여 병렬 처리할 수 있다.

### 멀티 프로세싱의 특징

- 여러 프로세스를 동시에 실행 가능
- 멀티코어 CPU 활용 가능
- 프로세스마다 독립적인 메모리 영역 사용
- 하나의 프로세스 오류가 다른 프로세스에 미치는 영향이 상대적으로 적음
- CPU 연산이 많은 작업을 병렬화할 때 효과적
- 프로세스 간 데이터 전달을 위해 IPC가 필요할 수 있음

IPC(Inter-Process Communication)의 대표적인 방법은 다음과 같다.

- Pipe
- Message Queue
- Shared Memory
- Socket
- Signal

### 멀티 프로세싱과 멀티 스레딩 비교

| 항목 | Multiprocessing | Multithreading |
|---|---|---|
| 실행 단위 | Process | Thread |
| 메모리 | 기본적으로 독립 | 같은 프로세스 메모리 공유 |
| 오류 격리 | 상대적으로 높음 | 상대적으로 낮음 |
| 데이터 공유 | IPC 필요 | 비교적 쉬움 |
| 생성 비용 | 비교적 큼 | 비교적 작음 |
| 멀티코어 활용 | 가능 | 실행 환경에 따라 가능 |

ROS에서도 여러 Node를 각각 별도의 프로세스로 실행할 수 있으며, 이러한 구조는 멀티 프로세싱의 한 사례로 볼 수 있다.


---

## 6. 분산 컴퓨팅(Distributed Computing)을 설명하라

**분산 컴퓨팅(Distributed Computing)**이란 네트워크로 연결된 여러 개의 독립적인 컴퓨터가 서로 통신하면서 하나의 작업 또는 시스템을 구성하는 컴퓨팅 방식이다.

멀티 프로세싱이 일반적으로 **하나의 컴퓨터 내부에서 여러 프로세서를 활용하는 것**이라면, 분산 컴퓨팅은 **여러 컴퓨터가 네트워크를 통해 협력한다는 것**이 핵심이다.

예를 들어 다음과 같은 구조를 생각할 수 있다.

    Computer A                 Computer B
    [Sensor Node] ──Network── [Processing Node]
                                   │
                                   │ Network
                                   ▼
                              Computer C
                              [Control Node]

각 컴퓨터가 독립적인 CPU와 메모리를 가지고 있지만 네트워크를 통해 데이터를 공유하면서 하나의 시스템처럼 동작한다.

### 분산 컴퓨팅의 특징

- 여러 컴퓨터의 자원을 함께 사용할 수 있음
- 네트워크를 통해 데이터를 교환함
- 시스템 규모를 확장하기 쉬움
- 물리적으로 떨어진 장치에서도 작업 가능
- 일부 장치가 고장나더라도 시스템을 계속 운영하도록 설계 가능
- 네트워크 지연이나 통신 장애를 고려해야 함

### 활용 사례

- 클라우드 컴퓨팅
- 대규모 웹 서비스
- 빅데이터 처리
- 분산 데이터베이스
- 자율주행 시스템
- 스마트 팩토리
- 다중 로봇 시스템
- ROS 기반 로봇 시스템

ROS2의 경우 DDS 기반 분산 통신을 사용하기 때문에 여러 컴퓨터에 ROS2 Node를 분산하여 실행하고 서로 Topic 등을 통해 통신하도록 구성할 수 있다.


---

## 7. 네트워크 통신(Network Communication)을 설명하라

**네트워크 통신(Network Communication)**이란 서로 연결된 두 개 이상의 컴퓨터 또는 장치가 정해진 통신 규칙인 프로토콜(Protocol)을 이용하여 데이터를 주고받는 것을 의미한다.

예를 들어 로봇 시스템에서는 다음과 같은 통신이 가능하다.

    Robot
      │
      │ Ethernet / Wi-Fi
      ▼
    Computer
      │
      │ Network
      ▼
    Server

각 장치는 네트워크를 통해 센서 데이터, 제어 명령, 영상 등의 정보를 전달할 수 있다.

### 네트워크 통신의 주요 구성 요소

#### 1. IP Address

네트워크에서 장치를 식별하기 위한 주소이다.

예:

    192.168.0.10

#### 2. Port

하나의 컴퓨터에서 어떤 프로그램 또는 서비스를 대상으로 데이터를 전달할 것인지 구분하기 위해 사용한다.

예:

    IP Address : 192.168.0.10
    Port       : 8080

#### 3. Protocol

통신하는 장치들이 데이터를 어떤 규칙에 따라 주고받을 것인지 정의한다.

대표적인 프로토콜에는 다음과 같은 것이 있다.

- TCP
- UDP
- HTTP
- MQTT
- RTPS

---

### TCP

TCP(Transmission Control Protocol)는 **연결 지향형 통신 프로토콜**이다.

주요 특징은 다음과 같다.

- 연결 설정 후 통신
- 데이터 전달 신뢰성 제공
- 데이터 순서 보장
- 손실된 데이터 재전송
- 흐름 제어 및 혼잡 제어 제공

따라서 정확한 데이터 전달이 중요한 환경에서 많이 사용된다.

---

### UDP

UDP(User Datagram Protocol)는 **비연결형 통신 프로토콜**이다.

주요 특징은 다음과 같다.

- 사전 연결 과정이 필요하지 않음
- 데이터 전달을 보장하지 않음
- 패킷 순서를 보장하지 않음
- TCP보다 프로토콜 오버헤드가 작음
- 낮은 지연이 중요한 통신에 사용할 수 있음

센서 데이터, 영상 스트리밍, 실시간 통신 등에서는 상황에 따라 UDP 방식이 사용된다.

### TCP와 UDP 비교

| 항목 | TCP | UDP |
|---|---|---|
| 연결 방식 | 연결 지향 | 비연결 |
| 신뢰성 | 높음 | 보장하지 않음 |
| 순서 보장 | O | X |
| 재전송 | O | X |
| 프로토콜 오버헤드 | 상대적으로 큼 | 상대적으로 작음 |
| 대표 용도 | 파일 전송, 웹 통신 등 | 실시간 스트리밍, 센서 데이터 등 |

### ROS와 네트워크 통신

ROS 시스템에서도 Node들이 서로 데이터를 주고받기 위해 네트워크 통신 기술을 사용한다.

ROS1에서는 대표적으로 TCPROS를 사용하며, ROS2에서는 DDS 및 RTPS를 기반으로 통신할 수 있다.

따라서 네트워크 통신은 하나의 컴퓨터 내부뿐 아니라 여러 컴퓨터와 로봇, 센서 및 제어 장치가 서로 정보를 주고받는 **분산 로봇 시스템을 구성하기 위한 핵심 기술**이라고 할 수 있다.
