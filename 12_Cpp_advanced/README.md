# 1. 일반 함수와 람다식의 차이

## 1.1 일반 함수란?

일반 함수(Normal Function)는 특정 작업을 수행하는 코드를
이름을 붙여 정의하고, 필요할 때 호출하여 사용하는 기능이다.

일반적으로 함수의 반환형, 함수 이름, 매개변수, 함수 본문을
명시하여 정의한다.

### 일반 함수 예제

```cpp
#include <iostream>
using namespace std;

int add(int a, int b)
{
    return a + b;
}

int main()
{
    cout << add(10, 20) << endl;
    return 0;
}
```

실행 결과:
30

일반 함수의 특징:
1. 함수에 이름이 존재한다.
2. 여러 위치에서 반복적으로 호출할 수 있다.
3. 함수의 선언과 구현을 분리할 수 있다.
4. 함수 자체는 주변 지역변수를 직접 캡처할 수 없다.
5. 함수 포인터를 통해 다른 함수에 전달할 수 있다.


## 1.2 람다식이란?

람다식(Lambda Expression)은 별도의 함수 이름을 정의하지 않고
함수처럼 호출할 수 있는 객체를 생성하는 C++ 문법이다.

C++11부터 도입되었으며, 주로 짧은 연산이나 특정 위치에서만
사용하는 동작을 간결하게 표현하기 위해 사용한다.

람다식은 컴파일러에 의해 클로저 객체(Closure Object)를
생성하는 형태로 처리된다.

### 람다식 기본 구조

```cpp
[캡처](매개변수) -> 반환형 {
    실행할 코드;
};
```

각 구성 요소:
- [캡처] : 외부 변수를 람다식 내부에서 사용할 방법 지정
- (매개변수) : 람다식이 전달받는 값
- -> 반환형 : 반환 데이터의 형식(생략 가능)
- { } : 실행할 코드

### 람다식 예제

```cpp
#include <iostream>
using namespace std;

int main()
{
    auto add = [](int a, int b) {
        return a + b;
    };

    cout << add(10, 20) << endl;

    return 0;
}
```

실행 결과:
30

위 코드에서 add는 일반 함수의 이름이 아니라
람다식으로 생성된 함수 객체를 저장하는 변수이다.


## 1.3 일반 함수와 람다식 비교

| 구분 | 일반 함수 | 람다식 |
|------|-----------|--------|
| 이름 | 함수 이름 필요 | 별도의 함수 이름 불필요 |
| 정의 위치 | 주로 네임스페이스 또는 클래스 영역 | 함수 내부에서도 정의 가능 |
| 코드 길이 | 별도 함수 정의 필요 | 짧게 작성 가능 |
| 외부 지역변수 | 직접 캡처 불가능 | 캡처 기능 제공 |
| 재사용성 | 여러 위치에서 재사용하기 편리 | 특정 위치에서 사용하기 편리 |
| 함수 전달 | 함수 포인터 등으로 전달 | 콜백이나 함수 객체로 전달 |
| 상태 저장 | 일반 함수 자체에는 캡처 상태 없음 | 캡처한 값을 객체에 보관 가능 |
| 주요 용도 | 공통 로직, 반복적인 기능 | 콜백, 정렬 조건, 간단한 연산 |


# 2. 일반 함수 대신 람다식을 사용할 때의 장점

## 2.1 코드의 간결성

간단한 작업을 위해 별도의 함수를 선언할 필요가 없다.

### 일반 함수 사용

```cpp
int square(int x)
{
    return x * x;
}

int main()
{
    int result = square(5);
}
```

### 람다식 사용

```cpp
int main()
{
    auto square = [](int x) {
        return x * x;
    };

    int result = square(5);
}
```

람다식은 기능을 사용하는 위치에 직접 정의할 수 있기 때문에
코드의 흐름을 파악하기 쉽다.

다만 여러 위치에서 반복적으로 사용하는 기능이라면
일반 함수가 유지보수에 더 유리할 수 있다.


## 2.2 외부 변수 캡처 기능

람다식의 가장 중요한 장점 중 하나는
자신이 정의된 영역의 지역변수를 캡처하여 사용할 수 있다는 것이다.

일반 함수에서는 다른 함수의 지역변수를 직접 사용할 수 없지만,
람다식에서는 캡처 기능을 통해 사용할 수 있다.

### 예제

```cpp
#include <iostream>
using namespace std;

int main()
{
    int value = 10;

    auto add = [value](int x) {
        return x + value;
    };

    cout << add(5) << endl;

    return 0;
}
```

실행 결과:
15

여기서 [value]는 외부 지역변수 value를
값으로 복사하여 람다식 내부에서 사용한다는 의미이다.

### 주요 캡처 방식

| 캡처 방식 | 의미 |
|-----------|------|
| [] | 외부 변수를 캡처하지 않음 |
| [=] | 필요한 외부 지역변수를 기본적으로 값으로 캡처 |
| [&] | 필요한 외부 지역변수를 기본적으로 참조로 캡처 |
| [x] | 변수 x를 값으로 캡처 |
| [&x] | 변수 x를 참조로 캡처 |
| [x, &y] | x는 값, y는 참조로 캡처 |

참고:
- 값 캡처는 일반적으로 캡처 당시의 값을 보관한다.
- 참조 캡처는 원본 변수에 접근할 수 있다.
- 참조로 캡처한 변수가 먼저 소멸하면 잘못된 메모리 접근이
  발생할 수 있으므로 객체의 수명에 주의해야 한다.


## 2.3 콜백 함수 작성이 편리함

콜백(Callback)은 특정 조건이나 이벤트가 발생했을 때
호출하도록 다른 함수에 전달하는 동작이다.

람다식을 사용하면 별도의 콜백 함수를 정의하지 않고
필요한 위치에서 직접 동작을 작성할 수 있다.

### 예제: 벡터 정렬

```cpp
#include <iostream>
#include <vector>
#include <algorithm>
using namespace std;

int main()
{
    vector<int> numbers = {5, 2, 8, 1, 3};

    sort(numbers.begin(), numbers.end(),
         [](int a, int b) {
             return a > b;
         });

    for (int n : numbers)
    {
        cout << n << " ";
    }

    return 0;
}
```

실행 결과:
8 5 3 2 1

람다식은 정렬 기준을 sort() 함수에 직접 전달한다.

일반 함수를 별도로 정의하지 않아도 되므로
정렬 기준과 실제 정렬 코드가 가까운 위치에 존재한다.


## 2.4 함수마다 서로 다른 상태를 유지할 수 있음

람다식은 외부 변수를 캡처하여 자신만의 상태를
보관할 수 있다.

```cpp
#include <iostream>
using namespace std;

int main()
{
    int start = 10;

    auto counter = [start]() mutable {
        return ++start;
    };

    cout << counter() << endl;
    cout << counter() << endl;

    return 0;
}
```

실행 결과:
11
12

mutable을 사용하면 값으로 캡처한 변수의
람다 객체 내부 복사본을 변경할 수 있다.

이때 main()의 원본 start는 10으로 유지된다.


## 2.5 최적화에 유리할 수 있음

람다식은 컴파일 시점에 구체적인 클로저 타입이 결정된다.

따라서 람다식을 템플릿 함수 등에 직접 전달하면
컴파일러가 호출 코드를 인라인으로 최적화하기 유리할 수 있다.

단, 람다식이 반드시 일반 함수보다 빠른 것은 아니다.
실제 성능은 컴파일러의 최적화와 호출 방식에 따라 달라진다.


## 2.6 람다식 장점 정리

1. 간단한 동작을 짧고 명확하게 작성할 수 있다.
2. 별도의 함수 이름을 만들 필요가 없다.
3. 외부 지역변수를 캡처할 수 있다.
4. 콜백 함수를 작성하기 편리하다.
5. 알고리즘의 조건을 사용하는 위치에서 직접 정의할 수 있다.
6. 캡처를 활용하여 독립적인 상태를 가진 함수 객체를 만들 수 있다.

결론적으로 람다식은 짧은 연산, 콜백, 이벤트 처리,
정렬 조건처럼 특정 위치에서 사용하는 기능에 적합하다.

반대로 여러 곳에서 재사용하거나 복잡한 동작을 구현할 때는
일반 함수가 더 적합할 수 있다.


# 3. 함수 포인터와 std::function 객체의 차이

## 3.1 함수 포인터란?

함수 포인터(Function Pointer)는 함수가 위치한 주소를
저장하고, 해당 주소를 통해 함수를 호출할 수 있는 포인터이다.

일반적인 데이터 포인터가 변수의 주소를 저장하는 것처럼
함수 포인터는 호출할 함수의 주소를 저장한다.

### 함수 포인터 기본 구조

```cpp
반환형 (*포인터이름)(매개변수형);
```

### 함수 포인터 예제

```cpp
#include <iostream>
using namespace std;

int add(int a, int b)
{
    return a + b;
}

int main()
{
    int (*funcPtr)(int, int) = add;

    cout << funcPtr(10, 20) << endl;

    return 0;
}
```

실행 결과:
30

설명:
- int (*funcPtr)(int, int)
  : 정수 두 개를 매개변수로 받고 정수를 반환하는 함수 포인터

- funcPtr = add
  : add 함수의 주소를 저장

- funcPtr(10, 20)
  : 저장된 함수 주소를 통해 함수 호출


## 3.2 함수 포인터의 특징

1. 함수의 주소를 저장한다.
2. 함수 호출 시 간접 호출이 가능하다.
3. 반환형과 매개변수형이 호환되어야 한다.
4. 캡처가 없는 람다식도 호환되는 함수 포인터로 변환할 수 있다.
5. 캡처가 있는 람다식은 일반 함수 포인터로 변환할 수 없다.
6. 저장하는 함수 포인터 자체에는 캡처 상태를 보관할 공간이 없다.

### 캡처 없는 람다식

```cpp
int (*funcPtr)(int, int) =
    [](int a, int b) {
        return a + b;
    };
```

위 코드는 정상적으로 사용할 수 있다.

반면 다음 코드는 불가능하다.

```cpp
int value = 10;

int (*funcPtr)(int) =
    [value](int x) {
        return x + value;
    };
```

[value]를 통해 외부 변수를 캡처한 람다식은
일반 함수 포인터로 변환할 수 없기 때문이다.


# 4. std::function 객체란?

## 4.1 std::function의 정의

std::function은 C++ 표준 라이브러리의 <functional> 헤더에서
제공하는 범용 함수 래퍼(Function Wrapper) 클래스 템플릿이다.

함수 포인터뿐만 아니라 람다식, 함수 객체 등
다양한 호출 가능한 객체(Callable)를 저장하고 호출할 수 있다.

내부적으로 타입 소거(Type Erasure) 기법을 사용하여
서로 다른 종류의 호출 대상을 동일한 함수 시그니처로 다룬다.

### 기본 구조

```cpp
std::function<반환형(매개변수형)>
```

예시:

```cpp
std::function<int(int, int)>
```

정수 두 개를 전달받고 정수를 반환하는
호출 가능한 대상을 저장할 수 있다는 의미이다.


## 4.2 std::function 사용 예제

```cpp
#include <iostream>
#include <functional>
using namespace std;

int add(int a, int b)
{
    return a + b;
}

int main()
{
    function<int(int, int)> func;

    // 일반 함수 저장
    func = add;
    cout << func(10, 20) << endl;

    // 람다식 저장
    func = [](int a, int b) {
        return a * b;
    };

    cout << func(10, 20) << endl;

    return 0;
}
```

실행 결과:
30
200

std::function은 호출 대상의 종류가 달라도
함수 시그니처가 호환된다면 동일한 변수에 저장할 수 있다.


## 4.3 std::function의 캡처 람다식 지원

함수 포인터와 std::function의 중요한 차이는
캡처가 있는 람다식을 저장할 수 있는지 여부이다.

### 예제

```cpp
#include <iostream>
#include <functional>
using namespace std;

int main()
{
    int value = 10;

    function<int(int)> func =
        [value](int x) {
            return x + value;
        };

    cout << func(5) << endl;

    return 0;
}
```

실행 결과:
15

std::function은 캡처된 상태를 가진 람다 객체도
저장할 수 있으므로 함수 포인터보다 활용 범위가 넓다.


# 5. 함수 포인터와 std::function 비교

| 구분 | 함수 포인터 | std::function |
|------|-------------|---------------|
| 정의 | 함수 주소를 저장하는 포인터 | 호출 가능한 객체를 저장하는 래퍼 |
| 헤더 | 별도 전용 헤더 불필요 | <functional> |
| 일반 함수 | 저장 가능 | 저장 가능 |
| 캡처 없는 람다 | 저장 가능 | 저장 가능 |
| 캡처 있는 람다 | 저장 불가능 | 저장 가능 |
| 함수 객체 | 직접 저장 불가능 | 저장 가능 |
| 상태 보관 | 자체적인 캡처 상태 없음 | 호출 객체의 상태 보관 가능 |
| 호출 비용 | 일반적으로 낮음 | 간접 호출 등의 추가 비용 발생 가능 |
| 메모리 비용 | 일반적으로 작음 | 상대적으로 클 수 있음 |
| 동적 메모리 | 포인터 자체에는 불필요 | 호출 객체에 따라 동적 할당 가능 |
| 사용 편의성 | 단순하지만 제한적 | 유연하고 범용적 |
| 주요 용도 | C API 콜백, 단순 함수 전달 | C++ 콜백, 이벤트 처리, 상태 있는 함수 전달 |


## 5.1 성능 측면의 차이

### 함수 포인터

함수 포인터는 함수의 주소를 통해 호출하는 방식으로
구조가 단순하고 저장 비용이 작다.

대체로 추가적인 객체 관리 비용이 거의 없다.

### std::function

std::function은 여러 종류의 호출 가능한 객체를
동일한 인터페이스로 다루기 위해 타입 소거를 사용한다.

따라서 다음과 같은 추가 비용이 발생할 수 있다.

1. 호출 대상의 간접 호출
2. 호출 객체 저장 및 복사 비용
3. 일부 호출 객체의 동적 메모리 할당

단, std::function이 항상 동적 메모리를 할당하는 것은 아니다.
일부 작은 객체는 내부 저장 공간을 활용할 수 있으며,
구체적인 최적화 방식은 표준 라이브러리 구현에 따라 달라진다.


## 5.2 빈 객체 호출 시 차이

함수 포인터와 std::function은 호출 대상이 없을 때의
동작에도 차이가 있다.

### 함수 포인터

```cpp
int (*funcPtr)(int) = nullptr;

// funcPtr(10);  // 정의되지 않은 동작
```

nullptr인 함수 포인터를 호출하면 정의되지 않은 동작이 발생한다.

### std::function

```cpp
#include <functional>

std::function<int(int)> func;

// func(10);  // std::bad_function_call 예외 발생
```

std::function이 비어 있을 때 호출하면
std::bad_function_call 예외가 발생한다.

두 방식 모두 호출 전 대상이 존재하는지 확인하는 것이 좋다.

```cpp
if (func)
{
    func(10);
}
```


# 6. 함수 포인터와 std::function의 선택 기준

## 함수 포인터가 적합한 경우

1. 일반 함수를 단순히 전달하거나 호출하는 경우
2. 캡처가 필요한 람다식을 사용하지 않는 경우
3. C 언어 API와 연동하는 경우
4. 저장 공간과 호출 오버헤드를 최소화해야 하는 경우

## std::function이 적합한 경우

1. 일반 함수와 람다식을 같은 형식으로 관리하는 경우
2. 캡처가 있는 람다식을 저장해야 하는 경우
3. 다양한 함수 객체를 교체하여 실행하는 경우
4. 유연한 콜백 및 이벤트 처리 구조가 필요한 경우

다만 std::function의 유연성이 필요하지 않고
호출 성능이 중요하다면 함수 포인터나 템플릿을 이용한
직접 호출도 고려할 수 있다.


# 7. 최종 결론

## ① 일반 함수와 람다식의 차이

일반 함수는 이름을 부여하여 정의하고 여러 위치에서
재사용할 수 있는 함수이다.

람다식은 이름 없는 함수 객체를 생성하는 표현식으로,
외부 지역변수를 캡처하고 필요한 위치에서 간결하게
동작을 정의할 수 있다는 장점이 있다.

따라서 람다식은 콜백, 이벤트 처리, 정렬 조건 등
짧고 특정한 목적의 동작을 구현할 때 유용하다.


## ② 함수 포인터와 std::function의 차이

함수 포인터는 함수의 주소를 저장하고 호출하는
단순한 포인터이다.

반면 std::function은 일반 함수, 람다식, 함수 객체 등
다양한 호출 가능한 대상을 저장하고 실행할 수 있는
범용 함수 래퍼이다.

함수 포인터는 구조가 단순하고 일반적으로 비용이 작지만,
캡처가 있는 람다식을 직접 저장할 수 없다는 제한이 있다.

std::function은 캡처가 있는 람다식까지 저장할 수 있어
활용 범위가 넓지만 추가적인 메모리 및 호출 비용이
발생할 수 있다.

결론적으로 단순한 함수 전달에는 함수 포인터를,
상태가 있는 콜백이나 다양한 호출 객체를 관리할 때는
std::function을 사용하는 것이 적합하다.
